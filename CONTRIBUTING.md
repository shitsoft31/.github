# Contributing to ShitSoft

First of all, thank you for considering contributing to ShitSoft! ❤️

Whether you're fixing a typo, reporting a bug, improving documentation, or developing a new feature, every contribution helps make the community better.

## Before You Start

Before starting work on a new feature or significant change:

* Check existing Issues and Pull Requests to avoid duplicate work.
* If no related Issue exists, create one and describe your idea.
* Wait for discussion if the change is large or affects existing behavior.

Small fixes (such as documentation, typos, or minor bug fixes) can be submitted directly as Pull Requests.

---

## Development Workflow

1. Fork the repository.
2. Create a new branch.
3. Make your changes.
4. Commit using Conventional Commits.
5. Push your branch.
6. Open a Pull Request.

---

## Branch Naming

Use descriptive branch names.

Examples:

```text
feature/user-authentication
feature/add-cli-support

fix/login-crash
fix/memory-leak

docs/update-readme
docs/api-reference

refactor/parser

test/add-unit-tests

chore/update-dependencies
```

---

## Commit Messages

This organization follows the **Conventional Commits** specification.

Examples:

```text
feat: add JWT authentication

fix: prevent null pointer dereference

docs: improve installation guide

refactor: simplify HTTP router

test: add parser unit tests

chore: update dependencies
```

Common commit types:

| Type     | Description                                  |
| -------- | -------------------------------------------- |
| feat     | New feature                                  |
| fix      | Bug fix                                      |
| docs     | Documentation                                |
| refactor | Code restructuring without changing behavior |
| test     | Tests                                        |
| style    | Formatting only                              |
| perf     | Performance improvements                     |
| build    | Build system changes                         |
| ci       | CI/CD changes                                |
| chore    | Maintenance tasks                            |

---

## Pull Requests

Please make sure your Pull Request:

* has a clear title;
* explains what changed and why;
* references related Issues when applicable;
* focuses on one logical change;
* passes any available tests.

Avoid mixing unrelated changes in the same Pull Request.

---

## Coding Style

Each repository may define its own coding conventions.

If a project contains formatting or linting tools, please run them before submitting your Pull Request.

---

## Be Respectful

Please be respectful and constructive during discussions and code reviews.

We welcome contributors of all experience levels and value helpful, collaborative feedback.

---

Thank you for helping build the ShitSoft community. 🚀
